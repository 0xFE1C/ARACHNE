# ADR-270 — Stage 22: supply chain, deployment, compliance & integrations

*Status:* accepted · *Stage:* S22 (Phase 4, gate G4) · *Date:* 2026-10-31

## Context

Phase 4's last work package makes ARACHNE pass a procurement review: a provable
toolchain for itself (SBOM, signing, provenance, a blocking dependency audit), a
deployable enterprise surface (Helm chart, HA, multi-worker, secrets), compliance
evidence (framework maps, framework reports, per-control exports) and the first
integration targets (DefectDojo-first, Jira, ServiceNow, SIEM, chat) — all without
touching the safety architecture (C-04).

## Decisions

### 270.1 — Compliance mappings are data, with a two-sided dangling-id gate

`templates/compliance/{cis,pci-dss,iso27001,nist-csf}.yaml` map check ids → controls.
`tests/unit/test_compliance_map.py` loads them with the *reference set* of check ids
taken from both the planning catalogue and the live registry — and first asserts the
catalogue and the registry agree with each other, so a check that vanishes from one
cannot leave the maps pointing at the survivor. The schema test is the guarantee the
requirement names; report-time loading omits the reference set so a stale custom map
degrades to honest `gap` rows instead of failing a report.

### 270.2 — Coverage is stated in three honest states, never "compliant"

Per control: `fail` (a mapped check produced a confirmed finding), `pass` (mapped checks
ran, nothing found), `gap` (mapped checks did not run — with the checks named). The
framework header states **mapped vs. the framework's own control count** (PCI DSS's 12
requirements, ISO 27001's 93 Annex A controls, CIS v8.1's 153 safeguards, NIST CSF
2.0's 106 subcategories), so the unmapped remainder is in the report, not an
implication. The join key is the qualified check id (`m3.sqli-oracle`): M1 and M2 both
ship a `favicon-hash`, and a bare-name join would conflate them. Report schema 1.5 →
**1.7** (1.6 was S21) adds the optional `compliance` block; no framework configured ⇒
no section ⇒ pre-S22 reports are byte-identical.

### 270.3 — The evidence export is a self-contained projection of the report

`arachne compliance export` writes one JSON document: framework identity, scan identity
(including the attestation), per-control state, failing findings **with their redacted
evidence payloads inline**, and the audit-trail summary. It is a pure function of the
report DTO — an export is evidence only if it never needs a live database to be
re-derived. `total_controls` is validated ≥ mapped count at load time.

### 270.4 — DefectDojo-first is structural: one builder, two delivery paths

`report/defectdojo.py` builds the `import-scan` document from the report DTO alone.
The webhook import and the new `defectdojo` report format (`arachne report --format
defectdojo`) render the *same document* — an offline deployment hands over the file and
DefectDojo sees what the online deployment pushes. Contract tests pin the shape against
a recorded receiver-side fixture (`tests/fixtures/integrations/`), not against our code.

### 270.5 — New integrations are payload shapes, not new clients

ServiceNow (Table API incidents, Basic auth, credentials enforced together with the URL
at construction) and the SIEM export join the existing webhook architecture: pure
rendering, `SecretStr` tokens, `ScopedHttpClient` egress scoped to the configured hosts,
failure audited and returned. The SIEM gets the one structural addition — `raw_body`:
NDJSON is line-delimited JSON, not a JSON document, so the sender posts it verbatim as
`application/x-ndjson`. Its records are the findings plus the scan's **audit events**
(fetched per scan by `ReportService.notify`; already redacted at capture), with a
timestamp fallback so every line carries one. The no-secrets-in-logs test delivers every
integration and asserts no token survives outside its header.

### 270.6 — The SBOM is a product artifact, generated by ARACHNE itself

`tools/sbom.py` emits CycloneDX 1.5 from the *installed* environment
(`importlib.metadata`, transitive, environment markers evaluated; a missing unmarked
dependency is a hard error). Byte-identical output for the same environment and
timestamp: sorted, `serialNumber` derived from the component set, clock from
`--timestamp` → `SOURCE_DATE_EPOCH` → now, in that order. The release workflow runs it
with the tag's commit timestamp. An operator runs the same tool against their own
environment — the artifact they attest to is the artifact they can regenerate.

### 270.7 — Signing is keyless and digest-addressed; the audit is blocking on tags

The release workflow signs the *pushed digest* with cosign keyless (GitHub OIDC
identity — nothing long-lived to rotate or leak), attests the SBOM to the same digest,
generates SLSA-style provenance via GitHub's official attestation action, and then
`cosign verify`es its own signature — a release that cannot be verified does not ship.
`pip-audit --strict` gates a tag with no `continue-on-error`; CI's job stays advisory on
branches (the S1 trade: a fresh CVE must not red-X unrelated work) and expresses the
blocking intent itself on tag refs. cosign is pinned via `COSIGN_VERSION`; actions by
major tag (SHAs documented as the stricter option); `pip-audit` upper-bounded in the
`audit` extra. `docs/reproducible-builds.md` separates deterministic from acceptable
non-determinism.

### 270.8 — The chart fails closed, and the credentials gate follows the surface

`deploy/helm/arachne` renders API (2 replicas + PDB + anti-affinity, uvicorn
`workers` per pod), an agent pool (external/internal mode), Postgres (StatefulSet or
external), and the migration Job as a pre-install/pre-upgrade hook. Every required
credential is a `required`/`fail` guard: **`helm install` aborts without them**
(REQ-OPS-006, the compose file's posture carried to K8s). Secrets reach pods via
`secretKeyRef`, an operator-managed `existingSecret` (mounted key file), or Vault Agent
injection annotations — the three sources the requirement names. The credentials gate
now scans `deploy/helm/` as shipped surface; the Kubernetes *pointer* idiom
(`secretKeyRef.key`, `secretName`, `existingSecret`, `topologyKey`) is recognised as
references (the same shape rule as `_FILE` env vars), as are `{{ … }}` template
references and empty structures — while a literal in a values file or template still
fails the gate (pinned by new tests).

### 270.9 — Multi-worker is per-pod; HA is per-deployment

`arachne serve --workers N` (env `ARACHNE_API_WORKERS`) passes uvicorn an import string
(`api.app.get_app`) so each worker builds its own services from the environment; one
worker keeps the historical app-object path byte-for-byte. The chart's HA story is
replicas + PDB + anti-affinity; the docs keep the S20 rule visible — counters are per
worker, gauges database-derived, Prometheus sums scrape targets.

## Consequences

- Report schema 1.7; catalogue unchanged; no migration (compliance block is computed,
  not stored — a report built later than the scan re-derives from the same stored rows).
- Two new pinned test files (`test_compliance_map.py`, `test_release_workflow.py`) plus
  `test_helm_chart.py` and `test_sbom.py` keep the release properties in the suite,
  which is what lets CI stay the arbiter on runners without helm/cosign installed.
- The integrations' recorded fixtures live in `tests/fixtures/integrations/` and are
  receiver-side documents; a receiver changing its schema is a fixture change, reviewed
  as data.
