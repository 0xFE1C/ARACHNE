The report QA gate (docs/spec/06- §10, docs/spec/07- §6).

`test_report_qa.py` builds one report from a **real full lab scan** — the shared stdlib web
lab (`tests/lab/web_lab.py`) with M1 (offline checks skip; js-asset-scan runs), M3 and M4
active checks, the analyzer and the correlation engine — and asserts, on the rendered
output:

1. every finding carries evidence refs, severity, confidence, provenance and remediation;
2. no unredacted secret appears in the Markdown or JSON (the lab's planted credentials are
   the canary);
3. the executive summary counts match the per-severity findings tables;
4. the JSON report validates against the versioned schema
   (`templates/report/report-schema-<version>.json`, generated by
   `python -m arachne.tools.report_schema`);
5. the Markdown follows the §9 skeleton, and low-confidence observations are kept out of
   the confirmed findings.

The SQL-backed report path (findings + `analysis_log` + `audit_log` rows) is exercised
separately in `tests/unit/test_report_store.py`, because it needs a database rather than a
rendered document.

## Golden files (S26)

`golden/` holds the committed artifacts of three requirements, compared byte-for-byte by
`test_ecos_golden.py` (reports) and `tests/integration/test_ui_ecos.py` (pages):

| File | Requirement | What it pins |
|---|---|---|
| `report-en.md` | reference locale | the English label vocabulary, byte-stable |
| `report-fr.md` | REQ-ECOS-005 | the second language's labels, headings and severity names |
| `report-mspp-fr.md` | REQ-ECOS-006 | white-label/MSSP mode: tenant branding, no ARACHNE attribution |
| `attack-path-graph.svg` | REQ-ECOS-004 | the attack-path visualization (verified vs candidate hops, cheapest break) |
| `posture-trend.svg` | REQ-ECOS-004 | the executive dashboard's severity trend, including a clean scan |
| `control-coverage.svg` | REQ-ECOS-004 | pass/fail/gap bands plus the hatched **unmapped** remainder |
| `ui-posture-page.html` | REQ-ECOS-004 | the executive dashboard page, normalized |
| `ui-attack-paths-page.html` | REQ-ECOS-004 | the attack-path page, normalized |
| `ui-quality-page.html` | REQ-ECOS-004 | tenant self-service for FP/risk acceptance, normalized |

On "golden screenshots": the suite has **no headless browser**, and adding one would trade a
deterministic gate for an installation dependency. The UI's visualizations are SVG the server
writes, so the committed `.svg` is the screenshot — diffable and reviewable in a pull request.
The pages carrying them are snapshotted as HTML. `code/docs/operator-guide.md` §42 says so
plainly rather than implying a pixel comparison.

Re-bless after an intended change:

```
ARACHNE_GOLDEN_UPDATE=1 pytest tests/report_qa/test_ecos_golden.py tests/integration/test_ui_ecos.py
```

The blessed run **fails on purpose** (a blessing must never pass silently in CI); re-run
without the variable. Review the diff before committing it — that diff is the review.

`tests/helpers/golden.py::normalize` collapses exactly two volatile tokens in the HTML
snapshots (the render timestamp and the operator label) and nothing else; the rest of the
document is compared verbatim.

`test_posture_golden.py` and `test_purple_golden.py` are the earlier (S23/S24) golden suites;
they compare rendered Markdown and JSON in-memory to pinned strings rather than to files, and
they still run alongside these.
